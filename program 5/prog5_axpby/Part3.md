Which scales better, the Part 1 fractal curve or AXPBY, and why?
The Part 1 fractal scales much better. With interleaved rows it reached about 7.5x at 8 threads. AXPBY with ./axpby -n 20000000 --sweep --check only got about 1.3x to 1.4x from 2 through 8 threads, and bandwidth leveled off around the mid-30s GB/s. The reason is arithmetic intensity since it is math done per byte moved. The fractal does up to 300 iterations of math per pixel, so it is compute-bound and extra cores stay busy. AXPBY does only a little math per element which is one multiply-add style update but must move a lot of data, so it is memory-bound. Once the memory bus is full, more threads do not help much.

Why does the program count 4*N*sizeof(float) bytes if each element only does 2 reads and 1 write?
The two reads are X[i] and Y[i], and the one write is result[i]. That is three floats. The extra factor is write-allocate, before the CPU can write result[i], the cache usually loads that cache line first, so result is counted as both a read and a write. That is two floats for X and Y plus two for result, which is four floats per element, or 4*N*sizeof(float) in total.
